# 🚀 Desafio Prático de Engenharia de Software: SENAC ADS

Bem-vindos ao repositório oficial do Desafio Prático de Desenvolvimento! 

Este projeto foi desenhado para simular a rotina real de um time de engenharia de software (Devs e Tech Leads). Vocês terão **45 dias** para planejar, codificar e entregar um MVP (Produto Mínimo Viável) que resolva um problema real do mercado financeiro e cooperativista.

---

## 🎯 Objetivo
Sair da teoria e colocar a mão na massa. O objetivo não é apenas entregar um código que funcione, mas demonstrar que o grupo sabe trabalhar em equipe, tomar decisões de arquitetura e comunicar suas soluções.

Lembrem-se da nossa regra de ouro: **Desenvolvimento de software é 50% código e 50% comunicação e processos.**

---

## 🗂️ Os Desafios Disponíveis

Cada grupo deverá escolher **apenas um** dos desafios abaixo. Navegue até a pasta de cada projeto para ler as especificações completas e os requisitos técnicos:

1. **SimulaCoop (Nível Fácil):** Um simulador de crédito focado em transparência, evolução de dívida e UI/UX.
2. **CoopVision (Nível Médio):** Um assistente de onboarding inteligente utilizando IA Multimodal para extração de dados de documentos.
3. **CoopShield (Nível Difícil):** Um motor anti-fraudes que monitora, analisa e bloqueia transações suspeitas em tempo real.
4. **Atualização Cadastral Inteligente** modernizando o processo de **atualização cadastral**, reduzindo a necessidade de digitação manual das informações presentes nos documentos enviados pelos clientes.
5. **Atualização Cadastral Inteligente** a evolução com OCR.

---

## ⚙️ Regras do Jogo (Como Participar)

1. **Formação das Equipes:** Os times devem ter **4 integrantes**. Definam os papéis (ex: quem fará o papel de Tech Lead, quem focará mais no Frontend, Backend, etc.), mas todos devem colocar a mão no código.
2. **Prazo de Entrega:** O projeto deve ser entregue (código no repositório + deploy) em exatamente **45 dias** a partir da data de início.
3. **Repositório:**
   - Um integrante da equipe deve fazer um *Fork* deste repositório.
   - Todo o código do grupo deve ser comitado no repositório *Forkado*.
   - Usem boas práticas de Git (commits semânticos, branches organizadas).

---

## 🏆 O Que Será Avaliado?

A avaliação final não será apenas "o código compila?". Nós avaliaremos:

* **Arquitetura e Boas Práticas:** O código está limpo, organizado e bem documentado? 
* **Trabalho em Equipe:** O histórico do Git mostra que todos participaram? As tarefas foram bem divididas?
* **UI/UX e Usabilidade:** A interface é amigável e resolve o problema proposto de forma clara para o usuário final?
* **Pitch de Entrega:** Como a equipe "vende" a solução. Vocês saberão explicar as decisões técnicas que tomaram?

---

## 🚀 Como Iniciar

1. Façam um *Fork* deste repositório.
2. Leiam atentamente o `README.md` do desafio escolhido.
3. Realizem a *Daily* inicial: dividam as tarefas iniciais e estruturem o Jira/Trello do grupo.
4. Mão no código!

Boa sorte e bom código a todos! Lembrem-se: os obstáculos técnicos fazem parte da rotina. Busquem as documentações, discutam em equipe e não tenham medo de refatorar.
